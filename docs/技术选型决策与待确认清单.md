## 二、待确认（技术选型，按紧急度排序）

### 🔴 阻塞 D1

**T1. Stitch MCP 的接入方式：OAuth 还是本地 proxy**

- 现状：`~/.codex/config.toml` 里 stitch 配的是 `X-Goog-Api-Key` 请求头 → 官方端点走 OAuth，不认 API key，所以报「身份验证已过期」
- 选项 A：官方托管端点改 OAuth（配置里删掉 header，UI 里点 Authenticate）
- 选项 B：换成本地 proxy（`@_davideast/stitch-mcp proxy`，读已配好的 ADC，token 自动续期）
- **建议**：先试 A，A 不通走 B（B 一定能通，因为 ADC 今天已经配好了）
- 影响：不通就没法让 Codex 拉设计稿存档，D1 第三步（提取 token）做不了

**T2. 样式方案：Tailwind 还是手写 CSS + tokens.css**

- 选项 A：**Tailwind v4（CSS-first，`@theme` 块直接吃 tokens）** —— 开发快，token 仍是唯一源
- 选项 B：**手写 CSS 变量 + scoped styles** —— 设计系统已经定得很细，手写更能体现"我在做设计系统"的叙事
- 选项 C：Tailwind 走 Nuxt 官方模块 + tokens 写进 config
- **建议**：A（Tailwind v4 的 `@theme` 把 oklch token 定义成 CSS 变量，utility 直接用，一套源两处受益）
- 注意：**需 D1 当天验证 Nuxt 4 + Tailwind v4 的当前集成方式**（v4 走 Vite 插件，不再是老模块），不要凭记忆抄配置

### 🟡 W2 前必须确认

**T3. 存储切换时机：records.json → SQLite**

- 现状：W1 用 JSON 文件，够用
- **建议**：W2 末，与批量功能一起做（`better-sqlite3` 或 Nuxt 生态的 `db0` 层）
- 影响：切换点决定 W2 是否要改数据访问层，越晚改越贵

**T4. GLM-4V-Flash 的免费额度上限与并发数**

- 为什么要：直接决定 `E_RATE_LIMIT` 的阈值和前端重试策略
- **动作**：注册智谱开放平台后，在控制台查额度文档，把数字写回 PRD 错误码表

**T5. 状态管理：Nuxt `useState` 还是 Pinia**

- 选项 A：Nuxt 内置 `useState` —— 够用（本项目状态集中在录入工作台一条流）
- 选项 B：Pinia —— 面试更"标准"，但要额外一层
- **建议**：A；如果 Codex 实现时发现跨页共享（记录列表 ↔ 工作台）变复杂，再上 Pinia

### 🟢 W4 再定

**T6. 部署平台**

- 候选：Vercel（Nuxt 零配置）/ Cloudflare Pages / 自建
- 约束：server routes + 文件写入 → **纯静态平台不行**，需要能跑 Node 的环境
- **建议**：W4 再说，别提前操心（唯一提前要做的是：图片存储别硬编码本地路径）
