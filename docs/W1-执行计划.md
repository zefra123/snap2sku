# W1 执行计划 · AI 商品录入助手

周期：10/6（周二）— 10/12（周一）｜投入：全职，每天 6-8 小时
目标：一周结束拿到「上传图片 → 识别 → 表单预填 → SKU 矩阵」的完整闭环

**纪律（每天执行）**：
- 每天下班前 git commit + push 到 GitHub（仓库明天第一天就建，开源从 Day 1 开始）
- 每个技术决策随手记进 `README.md` 的「设计取舍」一节，一句话即可——这是面试弹药的原始素材
- 卡同一个问题超过 1 小时，记录下来跳过，晚上统一处理或问我

**W1 范围纪律：只做 Web 管理端。uniapp 小程序端是 W3 的事，W1 碰都不要碰**——并行开工只会两边都烂。

## Day 1 · 10/6 周二 · 脚手架

**上午（3-4h）**

1. GitHub 建仓库（名字建议：`ai-sku-entry` 或 `snap2sku`，简介一句话写清定位）
2. 建本地 monorepo：

```
ai-sku-entry/
├── pnpm-workspace.yaml      # packages: apps/*, packages/*
├── package.json             # 根，只放公共 scripts
├── apps/
│   └── web/                 # Nuxt 4（npx nuxi@latest init web，当前默认 4.x；源码在 app/ 下，见 AGENTS.md §3）
├── packages/
│   └── shared/              # zod schema + 类型 + prompt 常量
│   └── prompts/             # 识别 prompt 单独一个包，版本化
└── README.md                # 第一天就写：定位 + 三条底线 + 设计取舍（空节）
```

3. 依赖：根装 `pnpm` workspace 后，`apps/web` 装 `zod`（workspace 协议引 `@scope/shared`）

**下午（3-4h）**

4. `packages/shared` 里先写空的 schema 骨架 + 导出，确保 web 端能 import 通
5. Nuxt 跑通 dev，首页放个标题和「上传区」占位
6. `.env` 方案：`NUXT_` 前缀环境变量，API key 走 `runtimeConfig`（**绝不能出现在前端 bundle**，这是面试必问的安全点，第一天就做对）

**验收**：`pnpm dev` 起服务，页面渲染，热更新正常，GitHub 上已有首个 commit。

---

## Day 2 · 10/7 周三 · 图片上传与压缩

1. 上传区组件：拖拽 + 点击，支持多选，只收 `image/*`
2. canvas 压缩：长边缩到 1024px、质量 0.85 输出 JPEG——把「原图体积 vs 压缩后体积」显示在页面上（这组数字要进 README，是实测数据）
3. Nuxt server route `/api/upload`：接收 base64/FormData，落到 `uploads/`，返回文件名
4. 上传失败的错误态、重试按钮

**验收**：拖 10 张手机拍的衣服图，页面显示每张的压缩前后体积，文件落盘。
**预埋的坑**：HEIC 格式手机图 canvas 解不出来，遇到就在上传前拦掉提示换 JPG（记进取舍）。

---

## Day 3 · 10/8 周四 · 多模态识别打通（本周最关键一天）

**上午**

1. 注册智谱开放平台，开通 GLM-4V-Flash（当前免费额度方案，超限再切通义）
2. 写 `packages/prompts` 里的识别 prompt v1（初稿见另一份文档，直接抄）
3. server route `/api/recognize`：读上传的图 → base64 → 调 GLM-4V → 拿回文本

**下午**

4. 剥壳函数：LLM 返回常带 ` ```json ` 包裹，先剥离再 `JSON.parse`
5. zod 校验：失败自动把校验错误信息拼进 prompt 重试 1 次，再失败就返回结构化错误给前端
6. 每字段带 confidence，前端先 console 打印

**验收**：单张图 → 终端打印出通过 zod 校验的结构化字段。
**预埋的坑**：免费接口有并发限制，多图先串行请求，W2 再做并发限流。

---

## Day 4 · 10/9 周五 · 表单预填

1. 动态表单：品类（select）、颜色（多选 tag）、风格、季节、人群——全部从 zod schema 的枚举生成，**不要手写选项列表**（这也是考点：schema 是唯一事实源）
2. AI 结果回填表单，每个字段旁显示置信度（低于 0.7 的标黄提示人工确认）
3. 用户改动任何字段时记录「AI 对/错」标记，写进本地记录——评测数据从第一天就开始攒
4. 多图合并：同一款多张图，v1 只取第一张识别结果，界面标注「多图融合 W2 做」

**验收**：上传 5 张同款不同角度的图 → 表单填好 → 手动改两个字段 → 记录文件里有本次数据。

---

## Day 5 · 10/10 周六 · SKU 矩阵

1. 识别出的颜色 × 标准尺码（S/M/L/XL 或鞋码）生成矩阵
2. 矩阵可增删行列，每格填「库存 + 吊牌价 + 批发单价」（吊牌价默认预填 AI 建议值）
3. 性能基准：先造 500 格的极端用例，肉眼测流畅度，用 Vue DevTools 记录渲染耗时——不管卡不卡都记下来，W2 优化时对比（这段经历面试直接讲）

**验收**：完整录入一件真实商品（拍照→表单→SKU→保存）。

1. 录入记录列表页：本次 W1 用本地 JSON 文件存储就够（`data/records.json`），别上数据库——取舍记进 README

**验收**：录入 3 件真实衣服，记录页能看到每件的耗时和 AI 准确标记。
