## W2 范围回顾

W2 把记录存储从易于起步的 JSON 迁移到 SQLite，启动时兼容导入旧记录并保留备份，以事务和 WAL 支持记录及 SKU 的一致写入；访问码门禁保护所有写接口，让本地未配置时仍可开发、部署配置后拒绝无码请求；描述生成功能按记录已有商品信息生成文案，通过 SSE 分段传给页面，并在完整流结束后保存，用户可看到生成过程及结果置信度。

## 实测记录

以下行为来自 [`docs/Code-Review-2026-10-09-W2D2.md`](Code-Review-2026-10-09-W2D2.md) 和 [`docs/Code-Review-2026-10-09-W2D2-P2fix.md`](Code-Review-2026-10-09-W2D2-P2fix.md)，均为本机 dev server 实测，不是本报告重新发起的接口测试。

- **SSE 时序**：mock 环境下 `curl -N` 观察到 10 个分片，分片间隔约 130ms，总时长约 2.5s，逐段到达，确认响应为真实流式输出。该实测值与 README 中按 200ms 推送的 mock 设计描述不同，报告保留评审记录的观测数据，不据此推断固定时序。
- **完整流与断流**：完整流保存 97 字描述；将请求在 0.5s 时断开后，数据库 `description_ai` 仍为 null。只有 `done` 事件写出成功才保存，符合“页面显示完整文案与数据库一致”的预期。
- **访问码与记录分支**：无访问码请求描述接口返回 401 `E_ACCESS_CODE_REQUIRED`；带正确访问码查询不存在的 ID 返回 404 `E_RECORD_NOT_FOUND`。
- **单条查询隔离**：评审将另一条记录置为无效 JSON 后，`getRecordById` 仍能读取目标正常记录；目标 ID 未命中返回 `undefined`。这避免 describe 路径被无关脏记录拖垮。
- **置信度**：完成后 SSE `result` 事件携带 description 与 overall 均为 0.88；页面在生成完成后显示描述置信度刻度尺。

## 已知限制

- **真模型尚未接入描述生成**：当前优先使用本地 mock；关闭 mock 后返回 `E_DESCRIPTION_UNAVAILABLE`。报告没有真实模型质量、成本或延迟数据。视觉识别的真实模型也缺少成功调用的仓库验收记录。
- **`E_WRITE_FAILED` 不能回传给已结束的流**：描述流已返回 HTTP 200 并发送终止事件后，若最终 SQLite 写入失败，服务端无法再通过该响应通知页面；该失败会由服务端记录。来源：W2-2 P2 修复评审的 P3 观察。
- **记录列表仍会全表解析**：`readRecords()` 仍对列表中的全部记录执行 schema parse；列表路径遇到脏记录可能整体失败。`getRecordById()` 只用于 describe 单条读取，其他调用点未改。
- **构建体积**：Nuxt/Nitro 报告总产物约 20.1 MB（9.55 MB gzip），其中包含 better-sqlite3 原生模块；部署前仍需评估目标环境兼容性与打包方式。
