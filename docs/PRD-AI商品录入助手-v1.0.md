### 1. 背景与目标

- 解决的问题：
  - 【事实】本项目为求职者的个人开源项目，需同时证明 AI 应用落地能力与前端工程能力；目标对标企业为服装行业全链路 SaaS（工厂→批发→零售）。
  - 【推断】服装商家进货录入是日常高频操作，人工填写品类/颜色/尺码/描述等几十个字段，单件耗时以分钟计。
- 目标（可度量）：
  1. 4 周内开源发布可公开访问的 Web 版 + 移动端录入；
  2. 识别准确率 ≥ 80%（50 张真实服装图、人工逐字段标注口径，W4 产出评测报告）；
  3. 单件商品录入耗时较纯人工降低 ≥ 50%（同人同款实测各 20 次，取中位数口径）；
  4. 单次识别 API 成本可显示、可追溯（页面实时展示估算成本）。

### 4. 流程

#### 4.1 主流程（录入一件商品）

```
1. 商家在 Web 端拖入 N 张照片（同一款，多角度）
2. 前端 canvas 压缩：长边≤1024px、JPEG 质量 0.85，展示每张压缩前后体积
3. POST /api/upload（逐张，FormData）→ 返回 fileId 列表，图片落盘 uploads/
4. 前端选第一张 → POST /api/recognize {fileId}
5. 服务端：读图→base64→调 GLM-4V-Flash→剥壳→zod 校验（失败带错误重试 1 次）
6. 返回 RecognizeResult（含逐字段 confidence）
7. 前端表单预填：枚举选项从 schema 生成；confidence<0.7 的字段标黄
8. 商家逐项确认/修改；每次修改记录进 edits[]
9. 商家在 SKU 矩阵填库存/吊牌价/批发单价（可增删行列；吊牌价列默认预填 AI 建议吊牌价 tagPrice，商家可改）
10. 点击「生成描述」→ POST /api/records/:id/describe（SSE）→ 流式渲染，可编辑；mock 模式逐段输出并写入 descriptionAi，`NUXT_VISION_MOCK=0` 时调用真实 GLM 描述模型生成后按 SSE 输出
11. 提交 → 服务端把记录与 SKU 写入 data/records.sqlite（事务内，含三段耗时埋点 + edits + 成本）
12. 列表页可见新记录
```

#### 4.2 分支流程

- 多张图：v1 只识别第 1 张并在 UI 标注「多图融合 v2 支持」（F-11）。
- 平台变体（F-10，可以有）：描述生成完成后可请求抖音/小红书/视频号三平台文案变体，SSE 复用描述生成的断流保护与成本累加口径（流完整走完才落库；断流不落库、不累加成本）。
- 压缩后体积 > 500KB：仍允许上传，列表中红色标出（不阻断）。
- confidence ≥ 0.85 的字段：正常样式，不提示。

#### 4.3 异常流程（详见第 6 节错误码表）

- 图片为 HEIC/非图片 → 前端拦截，提示换 JPG/PNG。
- 识别 API 超时/限流 → 自动退避重试 1 次，仍失败提示稍后再试。
- 模型输出过不了 zod → 重试 1 次后 422 返回 E_RECOGNIZE_INVALID。
- SSE 中断 → 前端保留已生成文本，提供「重新生成」按钮。

### 6. 异常分支处理

| 错误码                    | 触发条件                                                           | 系统处理                                   | 用户提示                           |
| ------------------------- | ------------------------------------------------------------------ | ------------------------------------------ | ---------------------------------- |
| E_ACCESS_CODE_REQUIRED    | 配置 NUXT_ACCESS_CODE 后，可写接口未提供正确访问码                 | 返回 401，不执行接口处理                   | 「访问码缺失或不正确」             |
| E_RECORD_NOT_FOUND        | 商品描述请求中的记录 ID 不存在                                     | 返回 404，不启动生成                       | 「找不到这条商品记录」             |
| E_DESCRIPTION_UNAVAILABLE | 未启用 mock 且未配置 NUXT_VISION_API_KEY                           | 返回 503，不调用模型                       | 「描述生成服务未配置」             |
| E_FORMAT                  | HEIC/非图片/伪造后缀（用文件头嗅探，非扩展名判断）                 | 拒绝，不入队                               | 「不支持该格式，请换 JPG/PNG」     |
| E_SIZE                    | 压缩后仍 >5MB                                                      | 拒绝                                       | 「图片过大，请裁剪后重试」         |
| E_FILE_NOT_FOUND          | 识别或读取缩略图时，fileId 不存在或对应上传文件已丢失              | 返回 404，不调用模型；提示用户重新上传图片 | 「找不到已上传的图片，请重新上传」 |
| E_UPSTREAM                | 视觉 API >20s 或 5xx                                               | 退避 2s 重试 1 次                          | 「识别服务开小差，正在重试…」      |
| E_RATE_LIMIT              | 免费接口并发超限                                                   | 队列串行化                                 | 「排队中，第 N 位」                |
| E_RECOGNIZE_INVALID       | zod 二次校验仍失败（含模型返回非 JSON，原 E_PARSE 场景已并入本码） | 422，不落任何数据                          | 「这张图没认出来，换个角度试试」   |
| E_VALIDATION              | 提交的 ProductRecord 未通过 schema 校验                            | 400，不落任何数据                          | 「商品数据不完整，请检查必填项」   |
| SSE 中断                  | 生成中断线                                                         | 前端保留已出文本                           | 「生成中断，点此继续/重新生成」    |
| 重复提交                  | 提交按钮连点                                                       | 提交后按钮 loading+禁用                    | 无需提示                           |
| E_WRITE_FAILED            | 写入 records.sqlite 失败                                          | 返回 500，不追加记录；保留前端表单内容     | 「保存失败，请保留表单内容后重试」 |

### 8. UI/UX 设计规范

#### 8.1 设计上下文（摘要，完整版见 `.impeccable.md`）

| 项       | 值                                                                           |
| -------- | ---------------------------------------------------------------------------- |
| 用户     | 服装档口商家/仓库管理员（高频录入、防错优先）+ 开源访客                      |
| 情感目标 | 可靠、利落、有来头                                                           |
| 方向     | **「档口工作台」工业实用风**：服装行业物件（吊牌、色卡、唛头）提炼的视觉语言 |
| 反参照   | 紫蓝渐变 / 毛玻璃 / 深色霓虹 / Inter/Roboto / 消费级大圆角卡片               |
| 主题     | 浅色单主题（暗色暂不做，取舍记 README）                                      |

#### 8.2 记忆点（Signature Element）：吊牌语言

AI 的每一次输出都以「吊牌」形态出现——这是全站唯一的记忆点，让界面一眼属于服装行业：

- **吊牌卡**：1px 虚线边框（`border: 1px dashed var(--c-primary-40)`），左上角一个 8px 打孔圆（`--c-bg` 底色圆点叠在边框上，纯平实现）
- 字段名用 sm 等宽字 + letter-spacing，字段值用 base 常规字
- **虚线 = AI 建议，实线 = 人工确认**：用户确认某字段后，该字段容器边框由虚线变实线（200ms 过渡）——数据来源永远可辨，这是本产品最重要的信任机制
- 置信度不做进度条（消费感），用 5 格刻度尺（`▮▮▮▯▯` 风格，CSS 实现，非字符），低于 3 格标 warning 色

#### 8.3 设计 Token（唯一实现位置：`apps/web/assets/css/tokens.css`，禁止散落硬编码）

**色彩（oklch，附 hex 近似值仅作参考）**

| Token                      | 值                                      | 用途                                             |
| -------------------------- | --------------------------------------- | ------------------------------------------------ |
| --c-bg                     | oklch(97% 0.008 80) ≈ #f6f4ef           | 页面底（暖纸白，非纯白）                         |
| --c-surface                | oklch(99% 0.004 80) ≈ #fdfcf9           | 卡片/表单面                                      |
| --c-ink                    | oklch(24% 0.012 60) ≈ #2b2924           | 主文字（非纯黑）                                 |
| --c-ink-2                  | oklch(46% 0.012 60) ≈ #6b675d           | 次级文字                                         |
| --c-border                 | oklch(87% 0.012 80) ≈ #d9d4c8           | 边框                                             |
| --c-primary                | oklch(40% 0.095 258) ≈ #2f4870          | 牛仔靛蓝：链接、选中态、focus ring               |
| --c-accent                 | oklch(52% 0.13 50) ≈ #b45f22            | 挂牌橙：仅主 CTA 与提交按钮（白字，须验 ≥4.5:1） |
| --c-success                | oklch(48% 0.10 150)                     | 保存成功                                         |
| --c-error                  | oklch(48% 0.15 28)                      | 校验失败、库存 0                                 |
| --c-warn-bg / --c-warn-ink | oklch(92% 0.06 90) / oklch(45% 0.09 85) | 低置信字段标黄底色/文字                          |

色彩纪律：60-30-10——暖纸底 60%，墨色文字与边框 30%，靛蓝+橙合计不超过 10% 的画面。中性色一律带暖偏移，禁 `#000`/`#fff`/纯灰。

**字体（3 族封顶）**

| Token          | 栈                               | 用途                                         |
| -------------- | -------------------------------- | -------------------------------------------- |
| --font-heading | 「思源宋体 Noto Serif SC」600    | 页面标题、区块标题（单据/文档感）            |
| --font-body    | system-ui 栈                     | 正文、表单                                   |
| --font-mono    | 「JetBrains Mono」→ ui-monospace | **一切数据**：价格/库存/耗时/成本/token/编号 |

- 字号固定 rem 阶梯（B 端密集 UI，不用 clamp 流式）：xs 0.75（单位、注释）/ sm 0.875（表格正文、标签）/ base 1（正文）/ lg 1.25（区块标题）/ xl 1.75（页面标题，全站最大）
- 数据类元素统一 `font-variant-numeric: tabular-nums`
- webfont `font-display: swap` + `size-adjust` fallback（Nuxt 可用 Fontaine 自动生成）

**间距 / 形状 / 动效**

| Token              | 值                           | 说明                          |
| ------------------ | ---------------------------- | ----------------------------- |
| --space-1..6       | 4 / 8 / 12 / 16 / 24 / 32 px | 4px 基准                      |
| --radius           | 4px                          | 工具感小圆角；吊牌卡 6px      |
| --shadow-card      | 0 1px 2px rgba(43,41,36,.06) | 极浅，仅一层；禁多层阴影/发光 |

| --t-fast / --t-mid | 150ms / 200ms                | hover / 状态切换              |

#### 8.4 布局与组件规范

- **主工作台（录入页）**：左 340px 上传队列（图片缩略图 + 每张压缩前后体积，mono），右侧表单 + SKU 矩阵；顶栏高 48px，含成本计数器（mono，实时）
- **上传区**：拖入态 = 虚线变实线 + 背景 2% 靛蓝着色（150ms）；队列缩略图按 4:3 裁切
- **SKU 矩阵**：表头 sticky；斑马纹用 --c-bg；单元格高 32px；数据列固定为 库存/吊牌价/批发单价（mono 右对齐），吊牌价列默认预填 AI 建议吊牌价；库存 0 显示 --c-error；行列删除用 hover 出现的 ×（触达区 ≥ 32×32px）
- **表单**：标签 sm 置于输入框上方（内浮标签禁用——B 端密集表单可读性差）；低置信字段背景 --c-warn-bg，修复后清除。字段集合以 5.1 schema 为唯一事实源（含适用人群 audience；Stitch 定稿参考稿未画全此字段，以 schema 为准补入表单）
- **流式描述区**：左缘 2px 靛蓝竖线 + 闪烁块状光标（1s 步进，reduced-motion 时静态）；生成完成后竖线消失、文本可编辑
- **记录列表**：单据风——表格 + mono 编号列，行点击展开吊牌卡（复用 8.2 组件）

#### 8.5 状态设计

| 状态           | 规范                                                                                  |
| -------------- | ------------------------------------------------------------------------------------- |
| 空状态         | 上传区居中：一句引导（「把到货的照片拖进来」）+ 支持格式与体积说明 + 「先看示例」入口 |
| 加载（识别中） | 上传队列对应缩略图边框呼吸（opacity 0.6↔1，1.2s）；按钮禁用并显示「识别中」           |
| 流式中         | 见 8.4；期间「生成描述」按钮变为「停止」                                              |
| 错误           | 第 6 节文案 + 对应语义色行内提示（不用 toast 弹错误详情，toast 只做成功确认）         |

#### 8.6 禁止清单（AI 编码代理硬约束）

1. 禁出现紫/蓝渐变、毛玻璃 backdrop-filter、霓虹发光、多层阴影
2. 禁用 Inter/Roboto/Open Sans 作为任何层级字体
3. 禁纯黑 `#000`、纯白 `#fff`、纯灰（chroma=0）
4. 禁动画化布局属性（width/height/top/left）；只用 transform/opacity
5. 禁回弹/弹性缓动（spring/bounce）
6. 禁用颜色作为唯一信息载体（低置信除标黄外必须同时有刻度尺数量差异）
7. 禁移动端隐藏核心功能（响应式降级只收布局，不砍流程）
