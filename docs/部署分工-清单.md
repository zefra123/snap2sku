## 二、必须由你做的（服务器 / 平台侧）

### A. 基础设施（一次性）

| #   | 动作                                | 说明                                                                                              |
| --- | ----------------------------------- | ------------------------------------------------------------------------------------------------- |
| A1  | 准备一台有持久化磁盘的 Linux 服务器 | SQLite 单写者，本地盘，不要网络盘/NFS                                                             |
| A2  | 域名解析到该服务器                  | 小程序端**强制要求 HTTPS + 已备案域名**                                                           |
| A3  | 安装运行时                          | Node **22.19.0 或更高的 22.x**（Nuxt 4.5.2 要求）、pnpm **11.19.0**（仓库 `packageManager` 锁定） |
| A4  | 安装 nginx、certbot、sqlite3 CLI    | sqlite3 CLI 用于一致性备份，不能用 `cp`                                                           |
| A5  | 防火墙放通 SSH/80/443               | 应用只监听 `127.0.0.1:3000`，**不要对外开放 3000**                                                |

### C. 只有你能拿到的机密 / 账号（我不会代填，也不该经过我）

| 键                                                                              | 在哪拿                                   | 填错会怎样                               |
| ------------------------------------------------------------------------------- | ---------------------------------------- | ---------------------------------------- |
| `NUXT_VISION_API_KEY`                                                           | 智谱开放平台 bigmodel.cn 控制台          | 识别全失败                               |
| `NUXT_VISION_INPUT_PRICE_PER_MILLION`<br>`NUXT_VISION_OUTPUT_PRICE_PER_MILLION` | 同上，**抄真实单价**                     | 为 0 则费用恒 0，**¥200 熔断直接失效**   |
| `NUXT_ACCESS_CODE`                                                              | 自己定一个字符串                         | 空则生产拒绝启动                         |
| `NUXT_UPLOAD_SIGNING_SECRET`                                                    | 服务器本地生成（见下）                   | 空则图片签名静默降级                     |
| `NUXT_TRIAL_RESERVE_CNY`                                                        | 单次调用预估上限                         | 空则用代码默认                           |
| `NUXT_TRIAL_ID`                                                                 | 自己定一个唯一标识（如 `trial-2026-10`） | 空则任务 12 只能按时间删，**有误删风险** |

密钥生成命令（**在服务器上跑，别把结果贴给我**）：

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

### D. 微信小程序平台（手册没写，但上线必须做）

1. 微信公众平台 → 开发管理 → 服务器域名：把你的 HTTPS 域名加进 **request 合法域名** 和 **uploadFile 合法域名**。
2. 小程序端构建时注入域名：`apps/mp/.env.local` 里写 `VITE_API_BASE_URL=https://<你的域名>`（该文件已被 gitignore，不会入库）。
3. 用微信开发者工具跑 `pnpm --filter mp build:mp-weixin`，上传并**提交审核**。真机调试时记得勾选「不校验合法域名」不是长久之计。

> 注意：仓库根 `pnpm build` **只构建 Web**（`pnpm --filter @snap2sku/web build`），小程序要单独构建。

- `.gitignore` 已含 `/deploy/env` → 复制过去的真实 env 不会被提交 ✓

## 六、上线验收清单（部署完成后逐条打勾）

- [ ] `systemctl status snap2sku` = `active (running)`
- [ ] journald 出现 `[store] 数据目录: /var/lib/snap2sku`，且显示**沿用已有账本**而非「新建空账本」
- [ ] `curl https://<域名>/api/health` → `{"status":"ok"}`
- [ ] 不带 `x-access-code` 请求 `/api/records` → **401**
- [ ] 带访问码请求 `/api/runtime-info` → `budget=200`、`spentCny` 非恒为 0（证明单价已生效）
- [ ] 上传一张图 → 识别成功 → 列表缩略图能显示（证明签名 URL 生效）
- [ ] 等 70 秒刷新页面 → 缩略图仍可显示（证明重拉列表换到新签名 URL）
- [ ] 编辑一条记录并保存 → 缩略图不 403（P0-2 回归）
- [ ] `systemctl restart snap2sku` → 额度累计值不归零
- [ ] `sqlite3 ... ".backup '...'"` 能成功，备份文件可用
- [ ] 小程序真机（非开发者工具）能上传并识别
