# snap2sku 服务器选购与备案清单

> 面向 ¥200 试用期的首次上线。配套：`docs/部署分工-清单.md`（上线动作分工）、`docs/运维-部署手册.md`（上机操作）。
> 写于 2026-10-23。**价格为 reference，一定以云厂商控制台实时价为准**——新用户秒杀和周年活动经常把年付打到很低。

微信小程序平台要求：**request / uploadFile 合法域名必须经过 ICP 备案**，还必须 HTTPS + 不能是 IP 或 localhost。这是强制项，不是建议。

|          | 路径 A：本轮带小程序           | 路径 B：本轮只上 Web                 |
| -------- | ------------------------------ | ------------------------------------ |
| 买哪里   | 中国大陆地域（上海/广州/北京） | 中国香港地域                         |
| 备案     | 必须，1–3 周                   | 不需要                               |
| 域名     | 必须已备案                     | 可用 IP 或境外域名                   |
| 上线节奏 | 备案期间可先用 IP 调通 Web     | 当天可用                             |
| 代价     | 时间                           | 小程序本轮不上，以后要上还得回头备案 |

**已决策：走路径 A（本轮带小程序上线）。** 下面的清单按 A 写，路径 B 相关内容保留作为退路参考。

### 今天就做（三件事，30 分钟）

1. 买域名并完成实名认证 —— **先做这个**，它是备案的前置。
2. 买服务器（同一家云，Ubuntu 24.04，2核4G，**时长选 3 个月以上**）。
3. 域名实名通过后立刻提交 ICP 备案 —— 下号要 1–3 周，早一天提交早一天上线。

买完之后就可以并行推进服务器上的部署了，不用干等。

## 一、买服务器

### 推荐配置（照着选）

| 选项     | 值                                                         | 为什么                                   |
| -------- | ---------------------------------------------------------- | ---------------------------------------- |
| 产品     | **轻量应用服务器 Lighthouse**                              | 别买 CVM，贵一倍且要自己配；别买 Windows |
| 地域     | 上海 / 广州                                                | 离用户近；具体哪个看你试用人群           |
| 镜像     | **Ubuntu 24.04 LTS**（选「操作系统镜像」，不要选应用镜像） | 手册第 1–7 步全是 systemd + apt 语境     |
| CPU/内存 | **2 核 4G**                                                | 见下方「为什么不要 2 核 2G」             |
| 系统盘   | 60–100G SSD                                                | SQLite + 上传图片，够用；图片多了再看    |
| 带宽     | 优先高带宽档（峰值 100–200Mbps 或 5Mbps 以上）             | 见下方「带宽别踩小水管」                 |
| 购买时长 | **≥ 3 个月**                                               | 备案硬要求，买 1 个月提交不了备案        |

### 为什么不要省那点钱买 2 核 2G

两个真实原因，都不是理论：

1. **构建会 OOM。** 部署手册第 3 步要在服务器上跑 `pnpm build`（Nuxt 4 全量构建）。2G 内存的机器跑 Nuxt build 很容易被 OOM killer 干掉，报错还很难看懂。
2. **原生模块必须在目标平台构建。** `better-sqlite3` 是原生模块，**不能**在 Windows 上构建好再上传到 Linux 用，必须在服务器上 `pnpm install` 现场装。所以构建这一步躲不掉。

已经买了 2 核 2G 的补救办法：

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
export NODE_OPTIONS=--max-old-space-size=1536
```

先用 swap 顶住，跑完 build 再决定要不要升配。

### 带宽别踩小水管

snap2sku 主流程是**拍照 → 上传 → AI 识别**。Nginx 模板的上传上限是 10m，手机原图动辄 3–5MB。3Mbps 档上传一张图要等好几秒，体验很差，而且用户会以为卡死了。宁可贵一点选高带宽。

### 价格参考（2026-10 官网口径，务必核对实时价）

腾讯云轻量国内地域大致分档：入门型 2核2G 约 ¥45/月起、通用型 2核4G 约 ¥100/月、高带宽「锐驰型」2核4G 活动价约 ¥72/月。年付通常是月付 ×12 的 85 折。促销季常见 2核2G 年付 ¥68–99 的秒杀。

阿里云轻量同档位价位接近。**建议域名和服务器买同一家**——备案必须在服务器所属的接入商提交，同家最省事。

预算一句话：**3 个月大约 ¥150–300 就能跑完试用期。**

## 二、买域名

1. 在**同一家云**的域名注册页买，`个人` 主体。
2. `.com` 首年约 ¥35–70，`.cn` 首年约 ¥25–40，差别不大，选 `.com` 通用些。
3. 买完立刻做**域名实名认证**（上传身份证），这一步不通过没法备案。
4. **实名认证通过后通常还要等 2–3 天**（WHOIS 同步 + 核验）才能提交备案，别指望买完当天就提交。

## 三、ICP 备案（最慢的一环，先做）

免费，云厂商都提供。流程：

```
提交资料 → 云厂商初审 1–2 工作日 → 短信核验（24 小时内要点）
→ 管局审核 20 个工作日内 → 下号
```

现实周期通常 **7–23 个工作日**。

个人备案的坑：

- **网站名称不能带经营性词汇**。个人主体网站常被要求改名，别写「XX商城」「XX云」「XX科技」这类，写偏工具类/个人类的名字通过率高。
- **snap2sku 的定位要提前想好措辞。** 这是「商品录入助手」，沾着电商/商户的边。个人备案审核口径偏紧，经营性内容（电商、金融、医疗等）容易被拒。填写时尽量描述成**工具类/个人项目**，别出现「商城」「交易」「商家入驻」这类词。真被驳回的话，退路是把备案主体换成个体工商户或公司。
- 备案主体信息必须和域名实名认证信息一致。
- 会有人脸核验（App 里做）和短信核验，别填错手机号。
- 备案期间 80/443 会被拦截，调试走非标端口，见下一节。

## 三·五、备案窗口期怎么熬（1–3 周）

这段时间是整个上线流程里最容易白等的，用对了能并行推进部署：

```bash
sudo install -o root -g root -m 0644 \
  /opt/snap2sku/current/deploy/nginx.staging.conf.example \
  /etc/nginx/sites-available/snap2sku-staging
sudo ln -s /etc/nginx/sites-available/snap2sku-staging /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
# 访问：http://<公网IP>:8080
```

三条纪律：

1. **别把域名解析到这台服务器。** 备案没下号就解析，等于主动把「未备案域名 → 境内 IP」的关联交给云厂商的扫描系统，常见后果是整台机器公网访问被关 24–72 小时。解析留到下号之后。
2. **别指望 80/443。** 未备案的境内服务器这两个端口会被拦，非标端口（8080）才是这段时间唯一走得通的路。
3. **别申请证书。** Certbot 的 HTTP-01 验证要求域名可解析且 80 端口可达，备案期间两条都不成立。等到下号后再跑。

这段窗口期正好用来：

- 把 `docs/运维-部署手册.md` 第 1–5 步跑完，确认 systemd 起得来、journald 里账本状态正常（这不是仅仅为了走流程——能把「80/443 被拦」之外的所有坑先排掉）。
- 用 `http://<公网IP>:8080` 跑 `docs/部署分工-清单.md` 第六节验收清单里**不需要 HTTPS 的那些项**（401 门禁、上传识别、签名 URL 60 秒过期、重启后额度不丢）。
- 顺手把 `NUXT_VISION_*` 两个真实单价抄进 `/etc/snap2sku/env` 并验证 `/api/runtime-info` 的 `spentCny` 不再是恒 0。

下号之后：恢复域名解析 → 换成 `nginx.conf.example`（80/443）→ `certbot --nginx` → 配小程序域名白名单 → 提审。

## 四、买了之后立刻要做的事

1. **安全组/防火墙**：放行 22、80、443。**3000 端口只对内网监听，绝对不要对外放行**（应用只绑 `127.0.0.1:3000`，外网要经 Nginx）。
2. **装运行时**：Node **22.19.0 或更高的 22.x**（Nuxt 4.5.2 硬性要求）、pnpm **11.19.0**（仓库 `packageManager` 锁定）、nginx、certbot、sqlite3 CLI。
   ```bash
   node --version   # 必须 v22.19+
   command -v node  # 记下这个绝对路径，手册第 5 步要用
   ```
3. 然后照 `docs/运维-部署手册.md` 第 1–7 步部署，填 `$NUXT_*` 环境变量。
4. 上线后跑 `docs/部署分工-清单.md` 第六节的验收清单逐条打勾。

## 五、关于省钱的一句话

这是试用期验证产品，不是跑生产。**别买多台、别上负载均衡、别买 RDS**——SQLite 是单写者模式，多台实例会直接错账（这也是部署手册反复强调 `instances: 1` 的原因）。一台轻量机 + 一个域名，够了。

跑完试用如果不继续，轻量服务器到期不续费即可；记得在此之前把 `records.sqlite` 和 uploads 备份下来。
