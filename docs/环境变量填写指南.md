# snap2sku 环境变量填写指南

> 对应 `deploy/env.example` → `/etc/snap2sku/env`。本文件只写**规则与来源**，不写真实值。
> 生成时间：2026-10-23。所有单价依据智谱开放平台官方定价页（open.bigmodel.cn）2026-10 口径。

---

## 速查表

| 键                                     | 填什么                                    | 填错的后果                            |
| -------------------------------------- | ----------------------------------------- | ------------------------------------- |
| `NUXT_ACCESS_CODE`                     | 自己定一个随机字符串                      | 空 → 生产拒绝启动                     |
| `NUXT_VISION_API_KEY`                  | 智谱控制台签发                            | 空/错 → 识别全部失败                  |
| `NUXT_VISION_INPUT_PRICE_PER_MILLION`  | **按你选的模型抄官方定价**                | 付费模型填 0 → 熔断失效               |
| `NUXT_VISION_OUTPUT_PRICE_PER_MILLION` | 同上                                      | 同上                                  |
| `NUXT_TRIAL_RESERVE_CNY`               | 单次调用预占金额，留空即 0.05             | 见下文，填小了没用                    |
| `NUXT_TRIAL_ID`                        | 本轮唯一标识                              | 空 → 任务 12 只能按时间删，有误删风险 |
| `NUXT_UPLOAD_SIGNING_SECRET`           | 32 字节随机值（你列表里没提，但生产必填） | 空 → 签名静默降级为无签名 URL         |

## 1. NUXT_ACCESS_CODE

自己定，不需要去任何平台申请。客户端每个受保护请求都要带 `x-access-code` 请求头，值与此一致。

```bash
node -e "console.log(require('node:crypto').randomBytes(24).toString('base64url'))"
```

要求：至少 20 字符；用 `base64url`（只含字母数字和 `-` `_`），**不要中文、空格、冒号、逗号**。

换码之后不用重启服务以外的操作：前端收到 401 会自动清掉本地旧码并弹出访问码输入面板，重新填一次即可。

## 2. NUXT_VISION_API_KEY

open.bigmodel.cn → 控制台 → API Keys → 新建。复制出来的形如 `xxxxxx.yyyyyyyy`，整串填进去。

不要把 key 提交到仓库——`/etc/snap2sku/env` 权限 600、仓库里也已经有 `.gitignore` 兜底。

## 3. 两个模型单价（最容易填错的一项）

**取决于你用哪个模型**，从官方定价页抄。当前仓库默认 `NUXT_VISION_MODEL=glm-4v-flash`。

| 模型                                | 输入（元/百万 token） | 输出（元/百万 token） |
| ----------------------------------- | --------------------- | --------------------- |
| **GLM-4V-Flash**（默认，4K 上下文） | **免费 → 填 0**       | **免费 → 填 0**       |
| GLM-4.6V-Flash                      | 免费                  | 免费                  |
| GLM-4.6V-FlashX（<32K）             | 0.15                  | 1.5                   |
| GLM-4.6V（<32K）                    | 1                     | 3                     |
| GLM-4.6V（32K–128K）                | 2                     | 6                     |
| GLM-5V-Turbo（<32K）                | 5                     | 22                    |

免费模型把单价填 0 是**正确的**，不是「没填」。定价以官方页为准，厂商会调整。

### 更正手册里的一句话

部署手册和分工清单都写过「单价为 0 则费用恒 0，熔断不会触发」。**这句话只对付费模型成立。**

看 `server/utils/budget.ts:106`：

```ts
const floorCny = reservation.reservedCny * Math.max(1, requestCount);
const costCny = Math.max(estimatedCostCny, floorCny);
```

结算取「真实费用」和「预占 × 请求次数」的较大值。所以即便真实费用是 0，每笔至少也会按预占额记账。免费模型下熔断依然会触发，只不过它实际约束的是**调用次数**而不是钱。

日志里会持续出现 `[trial-budget] 第 N 笔按估算记账`，这是预期行为，不是故障。

## 4. NUXT_TRIAL_RESERVE_CNY

每次模型调用先冻结的金额，调用结束后按 `max(真实费用, 预占 × 请求次数)` 结算。

- **留空**：代码取 `max(配置值 0, 历史兜底 0.05)` = **0.05**。
- 想收紧就往上填：`0.05` → ¥200 大约够 **4000 次**调用；`0.5` → 约 400 次；`1` → 约 200 次。
- **往下填没用**：小于 0.05 会被历史兜底顶回 0.05（除非已积累 20 笔以上非零费用，之后兜底变成「近 20 笔均值 ×2」）。

建议：这一轮**留空**，让默认 0.05 生效。真遇到刷量再调高。

## 5. NUXT_TRIAL_ID

本轮试用的唯一标识，纯字符串，随意但要能认出来：

```
NUXT_TRIAL_ID=trial-2026-10
```

用途是任务 12 按 trialId 精确清理测试数据。**留空的代价是只能按时间段删**，会误伤同期的其他数据，所以一定要填。

## 6. NUXT_UPLOAD_SIGNING_SECRET

你的清单里没列，但 `deploy/env.example` 里有，而且**生产必填**——图片读取签名密钥，空值会静默降级成无签名 URL（任何人都能读图）。

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

`NUXT_UPLOAD_SIGNING_SECRET_PREVIOUS` 只在轮换期间临时填，平时留空。

## 填完之后怎么验证

重启服务后，带访问码请求（把 `<IP>` 和 `<码>` 换成真实值）：

```bash
curl -s -H "x-access-code: <码>" http://127.0.0.1:3000/api/runtime-info
```

核对三点：

1. `budget` = 200、`spentCny` 和 `remainingCny` 都能读出来。
2. 不做任何识别时 `spentCny` 可以是 0（正常）。
3. **跑一次真实识别之后 `spentCny` 必须 > 0**（免费模型下也应 ≈ 0.05）。如果还是 0，说明预占没有生效，熔断是假的，别上线。
