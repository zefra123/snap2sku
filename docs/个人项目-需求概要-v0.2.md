## 一、项目定位

> **商家拍几张服装照片，AI 自动填好整个商品录入表单。**

一句话讲给面试官：「服装商家进货录入一件商品要填几十个字段，我做了个工具，拍照之后 AI 识别品类、颜色、风格，预填表单和 SKU 矩阵，再流式生成商品描述——录入时间从 A 分钟降到 B 分钟。」

### 双端形态

| 端 | 技术 | 场景 |
|---|---|---|
| 管理端（Web） | Nuxt 3 + TypeScript | 批量上传、复杂表单、录入记录管理 |
| 移动端 | uniapp（Vue3） | 拍照即录，仓库/档口现场使用 |

双端复用同一套 API 与类型定义（pnpm monorepo），这本身就是面试考点。

## 三、功能清单

### MVP（必须完成）

| # | 功能 | 说明 |
|---|---|---|
| 1 | 批量图片上传 | 前端 canvas 压缩后上传，展示压缩前后体积对比 |
| 2 | 多模态识别 | 每张图 → 结构化字段：品类、颜色、风格、季节、适用人群 |
| 3 | 表单预填 | 识别结果回填动态表单，商家逐项确认/修改 |
| 4 | SKU 矩阵 | 颜色 × 尺码自动生成矩阵，支持增删行列 |
| 5 | 商品描述流式生成 | 确认字段后流式产出描述文案，可编辑 |
| 6 | 录入记录 | 每次录入的耗时、AI 准确与否的标记，为评测积累数据 |

### V1（有余力再做）

- 多平台文案变体（抖音/小红书/视频号三种风格）
- 上传历史商品的相似款关联
- 批量导入图库链接（免上传）

### 明确不做（写进 README，面试讲取舍）

- 不做登录/多租户/权限体系
- 不做库存、订单等完整 ERP
- 不做模型微调，只用现成多模态 API
- 移动端不做原生 App

## 四、技术方案

```
monorepo (pnpm)
├── apps/web        # Nuxt 3 管理端（SSE 流式 + 复杂表单）
├── apps/mobile     # uniapp 小程序端（拍照 + 结果确认）
├── packages/api    # 共享 API 客户端 + zod schema
└── packages/types  # 端到端类型定义（schema → 前端类型自动推导）
```

- **识别**：多模态 API（Claude / GLM-4V / 通义，做成可切换适配器），prompt 强约束 JSON 输出，zod 校验失败自动重试
- **流式**：Nuxt server routes 代理 SSE，前端打字机渲染
- **表单**：SKU 矩阵展开后可达数百输入框——动态表单性能是这个项目最硬的前端考点
- **成本**：按图片 token 估算单次录入成本，页面实时展示（这个数字面试极好用）

## 五、面试弹药清单（能讲 30 分钟的 8 个点）

| # | 会被问 | 你要能答到 |
|---|---|---|
| 1 | AI 返回的 JSON 怎么保证能进表单？ | prompt 约束 + JSON schema + zod 校验 + 失败重试与降级 |
| 2 | 为什么在前端压缩图片？ | canvas 压缩参数取舍、体积与识别准确率的平衡、实测数据 |
| 3 | SKU 矩阵几百个输入框怎么不卡？ | 动态字段渲染策略、按行列分块、非受控/受控取舍 |
| 4 | 流式渲染怎么不丢帧？ | SSE 与 WebSocket 取舍、rAF 批量更新、断线处理 |
| 5 | 双端怎么复用代码？ | monorepo 结构、schema 单一来源、端能力差异的适配层 |
| 6 | 单次录入成本多少？ | 图片 token 计算、模型分级（识别用便宜模型，描述用好模型） |
| 7 | 你怎么证明识别是准的？ | 人工标注流程、准确率/召回率口径、badcase 归因 |
| 8 | 小程序端和 Web 端交互差异？ | 拍照交互、弱网上传队列、离线暂存的取舍 |

**纪律：做的时候每个决策随手记进 README 的「设计取舍」一节，面试照着讲，不临场编。**

## 六、数字目标（做之前定死，做完填数）

| 指标 | 目标 | 口径 |
|---|---|---|
| 识别准确率 | ≥ 80% | 50 张真实服装图，人工逐字段标注 |
| 录入耗时对比 | 人工 vs 工具至少省 50% | 自己实测各 20 次，记录中位数 |
| 单次录入成本 | ≤ 0.1 元 | 按实际 API 账单折算 |
| 描述编辑率 | 记录即可 | description 终值 ≠ AI 原文（descriptionAi 留存）的记录占比（衡量生成质量） |
| 发布后 | 100 star 或 3000 阅读 | 开源 + 一篇有数据的文章 |

## 七、4 周里程碑

| 周 | 交付物 | 完成标志 |
|---|---|---|
| W1 | 最小闭环 | 单图上传 → 识别 → JSON 校验 → 表单预填，Nuxt 工程搭好 |
| W2 | 管理端成型 | 批量上传、SKU 矩阵、流式描述、成本统计 |
| W3 | 移动端 | uniapp 端拍照录入（兜底方案：H5 移动适配，面试讲清取舍） |
| W4 | 评测 + 发布 | 50 张图标注完、部署上线、开源、发文 |

**两个超期风险提前说**：
- W3 小程序端最容易爆——如果没有微信小程序测试资质或时间不够，直接降级为 H5 移动端，核心故事不变；
- W4 的标注别拖到最后一晚，50 张图 × 8 个字段的人工标注大约要一个晚上，W3 就穿插着做。
